# Module d'op1_249 (maiko) dans la build

[op1_249](https://maikopruett.com/op-1) est un firmware publié par maiko, construit sur op1r 12. Il ajoute :
- l'annulation / rétablissement de la bande (TAPE + ← / →), avec une popup comme sur l'OP-1 field ;
- les noms de snapshots, sur un écran en forme de bobine ;
- le mode gamme (`/yaffs2/user/scale.cfg`) ;
- une barre de stockage sur l'écran COM ;
- des journaux dans `/log`.

Ses sources ne sont pas publiées. Son **module binaire** peut être chargé dans notre build, à côté d'op1r 27, de roll
et de drive :

```sh
cd synth_sdk
python3 make_firmware.py --opz --native --module /chemin/vers/op1_249.op1
# -> ../op1_246_custom-repacked.op1, écran de démarrage « op1r 27+249 <date> »
```

`op1_249.op1` est **ta copie** de l'image de maiko (sha256
`b7adf5c0fdd523a726e81880e683eda48061a261944dfa1a7a52c57ebfc41066`). Rien de cette image n'est dans le dépôt :
seuls son sha256 et des adresses figurent dans `MODULES` (`make_firmware.py`). **Ne pas diffuser** une image
construite avec `--module` sans l'accord de maiko.

## État

| | État |
|---|---|
| op1r 12 + roll + drive + module 249 (ancienne construction binaire) | flashé, « tout bon pour l'instant » |
| op1r 27 + roll + drive + module 249 (cette construction) | construite et vérifiée hors ligne (ci-dessous) ; **pas encore flashée** |

## Ce que fait `--module`

1. Vérifie le sha256 de l'image : seules les images listées dans `MODULES` sont acceptées.
2. Copie ses trois blocs à l'adresse où maiko les a liés :
   - `01e40000-01e76558` : code et données ;
   - `01e76558-01eb7464` : variables (bloc FILL) ;
   - `02800000-02980000` : tampon de 1,5 Mo (bloc FILL).

   Ces zones ne recouvrent rien : notre code finit à `01e2c3d8`, notre BSS commence à `01ec0000` (op1r 27 laisse
   ce trou exprès), et le firmware d'origine n'utilise pas `02800000`. Un recouvrement arrête le build.
3. Copie ses 19 sites patchés dans le firmware d'origine. Le build vérifie que chacun contient encore les octets
   R246 d'origine, donc qu'aucun n'est déjà patché par op1r, roll ou drive.
4. Lui donne les deux `CALL` du KeyHandler (touches `019c2d3e`, encodeurs `019c2e94`). Ses hooks traitent leurs
   touches puis sautent en fin de chaîne vers op1r 12 (`JUMP.L` en `01e4064a` et `01e406ae`). Ces deux sauts sont
   recalés sur nos `key_event_hook` et `knob_event_hook`, dont l'éditeur de liens donne l'adresse.

Non copiés : son texte de démarrage et ses deux chaînes « Rev. 00249 » (cosmétiques).

## Pourquoi c'est sûr de le faire en binaire

Analyse de `bfin-elf-objdump` du code du module (`01e40000-01e47ba0`) :
- il appelle des fonctions du firmware d'origine, et **seulement deux** fonctions d'op1r 12 : ses hooks touches et
  encodeurs, en fin de chaîne ;
- il ne contient aucune adresse de constante vers le bloc d'op1r : il ne lit aucune donnée d'op1r.

Il ne dépend donc pas de la version d'op1r. Le module ne change que lorsque maiko publie une nouvelle image. Il
faut alors une nouvelle entrée dans `MODULES`, après la même vérification.

Contrôle de l'image construite :
- le bloc de code du module est identique à celui d'op1_249, aux 4 octets des deux sauts près ;
- les deux sauts visent `key_event_hook` et `knob_event_hook` ;
- les 19 sites sont identiques à ceux d'op1_249.

## Interactions avec op1r 27

- **Ordre des hooks** : le module voit les touches et les encodeurs avant op1r, roll et drive. TAPE + ← / → est à
  lui.
- **`0x0191c750`** (« presse-papiers de la bande inactif ») : le module remplace cette fonction. Il renvoie
  « occupé » tant qu'une écriture d'annulation est en cours. Le punch in / out d'op1r l'appelle avant d'enregistrer :
  il attend donc la fin de ces écritures, ce qui est voulu.
- **Boucle principale** : le module accroche `019f0a2a` et `019f0a3c`, le compte à rebours d'op1r `019f0a24`.
  Ce sont trois appels distincts.
- **Base de données** : le module écrit dans la table `clips` de la bande (`UPDATE` / `INSERT` / `DELETE`) ; op1r 27
  limite le cache SQLite de chaque base (24 pages pour `tape.db`).
- **Fonctions arrivées après op1r 12** (marqueurs, punch, compte à rebours, sorties USB, éditeur d'échantillons) :
  aucun site commun ; à essayer avec l'annulation (par exemple annuler un enregistrement fait par punch).

## Revenir à un firmware sans le module

L'historique d'annulation reste sur le disque (`/yaffs2/user/undo*`), ainsi que `scale.cfg` et `/log`. Un firmware
sans le module les ignore, mais l'historique continue d'occuper de la place sur le disque.

## À terme

op1_249 intègre le code d'op1r, qui est sous GPL. La licence d'op1r (`NOTICE`) demande à qui distribue une telle
image d'en fournir les sources complètes. Les demander à maiko permettrait de porter ses modules en sources, comme
roll et drive.
